1. Executive Summary

This project is a multi-tenant enterprise RAG + agentic automation platform. Companies upload policies/SOPs; authenticated users ask questions; answers are produced by tenant-filtered vector retrieval + an LLM, with citation validation and guardrails.

Who uses it

  • platform_admin (tenant platform) — creates companies; invites each company’s first admin
  • company admin — manages users inside its own company only
  • user — upload / chat within own tenant

Live AWS AI path (infra/terraform/envs/dev/main.tf):

  • AI_PROVIDER=hybrid
  • EMBED_PROVIDER=cohere → embed-multilingual-v3.0 (1024-d)
  • LLM_PROVIDER=groq → openai/gpt-oss-20b
  • QDRANT_COLLECTION=ekba_chunks, distance COSINE, Qdrant Cloud URL

User Browser
  ├─► Amplify (Next.js UI) ── HTTPS
  └─► CloudFront (API HTTPS edge)
        └─► ALB ekba-dev-alb
              ├─ :80  production → TG ekba-dev-blue  (or green after shift)
              └─ :8080 test      → TG ekba-dev-green (CodeDeploy health)
                    └─► ECS Fargate task ekba-dev  (PUBLIC subnets, assign_public_ip=true)
                          ├─ api (FastAPI :8000)
                          ├─ redis sidecar :6379
                          └─ qdrant sidecar (still started; UNUSED when QDRANT_URL=Cloud)

FastAPI talks to:
  Cognito (JWT JWKS) | RDS ekba-dev-postgres (private subnets)
  S3 documents       | Secrets Manager ekba/dev/*
  Qdrant Cloud       | Cohere Embed | Groq Chat
  Bedrock (vision / optional providers) | Transcribe (media)
  CloudWatch logs

CI/CD:
  GitHub → Actions OIDC → ECR ekba-dev-backend → CodeDeploy ekba-dev / ekba-dev-dg
Network fact: There is no NAT Gateway. ECS tasks run in public subnets with public IPs. RDS runs in private subnets, reachable only from the tasks security group.

4. Request Flows

Auth principal: Bearer Cognito ID token → verify_token (backend/app/core/auth.py) → RequestContext.tenant_id / role from verified claims only (never from request body).

A) Login

  1. Frontend → POST /api/v1/auth/login
  2. Anonymous rate limit → Cognito USER_PASSWORD_AUTH (or local dev auth)
  3. Returns ID token + refresh; stamps users.last_login_at; audit auth.login_succeeded

B) Company creation

POST /api/v1/platform/tenants — requires PlatformAdminUser → row in tenants via control plane.

C) User invitation

  • First company admin: POST /api/v1/platform/tenants/{tenant_id}/admins
  • Inside company: POST /api/v1/admin/users (roles limited to user/admin)
  • Writes Postgres user + Cognito invite (OTP password; app never stores passwords)

5. Master Realistic Example

Company tenant + user "Rahul"
  → POST /api/v1/auth/login → Cognito ID token (custom:tenant_id, custom:role)
  → CloudFront → ALB :80 → ECS FastAPI
  → POST /api/v1/documents  (Employee Travel Policy.pdf)
  → S3 key: {tenant_id}/{uuid}.pdf  (AES256)
  → Postgres documents + ingestion_jobs
  → Background: pypdf extract → chunk 512/64
  → Cohere embed-multilingual-v3.0 (1024-d)
  → Qdrant Cloud collection ekba_chunks (tenant-scoped upsert)
  → POST /api/v1/chat  "What is the daily meal allowance?"
  → injection scan → question embed → Redis semantic cache miss
  → Qdrant search MUST filter tenant_id (+ exclude suspicious=true)
  → score ≥ 0.35 → BM25+vector rerank → top_k=8
  → SYSTEM_PROMPT + sources → Groq openai/gpt-oss-20b
  → citation validation + output guardrail
  → answer + citations → usage/messages → UI

8. RAG Pipeline

Exact order in backend/app/services/rag/pipeline.py:answer_question:

  1. Authentication (route dependency)
  2. Input validation (validate_question)
  3. Prompt injection scan (scan_input) — may block
  4. Embed question
  5. Semantic cache (Redis, tenant-namespaced) — cache hit still runs output guardrail
  6. Qdrant search — tenant filter built inside vector.search (cannot omit)
  7. Relevance threshold: 0.35 (local stub uses 0.15)
  8. Over-fetch top_k * 2 then BM25+vector rerank → retrieval_top_k=8
  9. Context construction + system prompt
  10. LLM chat
  11. Citation validation ([S1]… must match retrieved sources)
  12. Output guardrail
  13. Usage tracking (+ cache store if citations OK)

Reranking: local BM25 fusion (rerank.py, lexical weight 0.35) — not a hosted Cohere/Bedrock reranker.

Chunking: 512 / 64 tokens.

23. Destroy → Deploy Lifecycle

./scripts/destroy.sh (dev only): create manual RDS snapshot → terraform destroy dev state.

Survives: baseline (Cognito, ECR, S3 bucket, Secrets, budget), cost-guard, frontend (Amplify/CloudFront), state bucket, RDS snapshots, Qdrant Cloud data (external).

./scripts/deploy.sh: recreate ephemeral stack → restore newest RDS snapshot → ECS/CodeDeploy → verify.

./scripts/deploy-frontend.sh: Amplify + CloudFront wiring.

25. Interview Q&A

QuestionStrong answer
Why Qdrant?Payload filters + COSINE + tenant index; filter is built inside vector.search so callers cannot omit it.
Why embeddings?Semantic retrieval over policies; same model for index and query.
Why RAG?Ground answers in company docs; citations validated against retrieved chunks.
Why Cohere?Configured live embed path (embed-multilingual-v3.0, 1024-d); Titan remains a config alternative.
Why PostgreSQL?Relational tenancy, jobs, audit, usage — durable across task replacement via RDS snapshots.
Why S3?Durable originals with tenant-prefixed keys generated server-side.
Why Cognito?Managed IdP; app never stores or sets passwords.
Why Redis?Ephemeral rate limiting + semantic cache; cheap sidecar, no ElastiCache cost.
Why ALB / ECS / CodeDeploy?Fargate + blue-green with a dedicated test listener before traffic shift.
Why CloudFront / Amplify?HTTPS UI/API for users while ALB stays HTTP-only.
Tenant isolation?JWT tenant only → SQL filters, S3 prefix checks, mandatory Qdrant tenant filter.
ECS crash?Target health fails; traffic stops; new task; 5xx alarm can auto-rollback deploy.
Manual rollback script?rollback.sh traffic shift is not implemented yet; CodeDeploy auto-rollback is.
Where are secrets?AWS Secrets Manager under ekba/dev/... — never in git or frontend.
Cost control?No NAT/EKS/ElastiCache; destroy after demo; gross spend guard near $18.
